# Charlie B

I build software and research systems for consequential automation: AI agents, security, financial workflows, and quantitative research.

A recurring question connects most of my work:

> If a system makes an important claim, can we verify it independently?

I am drawn to problems where correctness, provenance, observability, and failure modes matter as much as features.

## Selected work

### Agent Control Verification + Agent Action Integrity Observatory

[Agent Control Verification](https://github.com/MrC8559/Agent-control-verification) is an open-source agent-security research project focused on whether control decisions agree with independently observed effects.

ACV includes decision/effect verification, approval binding and replay checks, explicit failure-posture modelling, redacted evidence bundles, and a version-pinned Codex probe. It is the verification engine for the broader [Agent Action Integrity Observatory](https://github.com/MrC8559/Agent-control-verification/blob/main/docs/ACTION_INTEGRITY_OBSERVATORY.md), a research programme intended to accumulate narrow, reproducible observations across exact host versions and execution paths.

The project is experimental and pre-alpha. Its first real-host evidence milestone is in progress, and it deliberately avoids host-wide security scores or certification claims.

[10-minute technical review](https://github.com/MrC8559/Agent-control-verification/blob/main/REVIEWER_GUIDE.md)

### ChainTax

Founder and builder of [ChainTax](https://chaintax.co.uk), a live UK crypto-tax product for complex exchange, wallet, DeFi, NFT, staking, and liquidity-pool activity.

The system is built around deterministic tax logic, reconciliation, visible uncertainty, audit evidence, production testing, and clear professional-review boundaries. The production codebase is private.

[Read the public engineering case study](case-studies/chaintax.md)

### Northlight

**Northlight** is a private quantitative research lab focused on predeclared experiments, reproducibility, realistic cost modelling, provenance, preserved negative results, and strict separation between research evidence and execution.

The project treats trading as a downstream consequence of successful research rather than the starting assumption. Current work remains research and paper-only.

## How I work

- make important claims testable;
- prefer reproducible evidence over impressive demos;
- preserve uncertainty instead of forcing a confident answer;
- treat negative results as useful research output;
- use AI as an engineering multiplier, not as a substitute for verification.
